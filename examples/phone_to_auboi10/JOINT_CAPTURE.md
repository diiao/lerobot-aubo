# AUBO i10：沿用旧手机遥操的七维关节示范采集

**2026-09-22 后续更新：用户明确选择完全恢复旧手机遥操。当前契约为 `AuboI10JointLegacyTeleopV2`，J5 跟随逆解，不再固定 90°；六个关节加吸盘共七维。此前固定 J5 的六维数据、检查点和真实模型验证结果不适用于此版本。**

这条新路线使用 `record_joint.py`，旧 C0/TCP 入口及历史数据保留。修改前的代码存档为 `c216081`。新入口尚未完成真机采集验证；不要直接投入整批录制。

## 模型到底学习什么

| 项目 | 定义 |
| --- | --- |
| 图像输入 | CameraSetV2 的 global_rgb、grasp_rgb，两路 RGB |
| 数值状态输入 | J1、J2、J3、J4、J5、J6、gripper_pos，共 7 维 |
| 动作输出 | 上述六个关节的绝对目标角度，以及吸盘指令，共 7 维 |
| 第五轴 | 沿用旧手机逆解结果，参与记录与模型预测 |
| 单位 | 数据中的关节角度为度；发送给 AUBO SDK 时转换为弧度一次 |
| 吸盘 | 0=释放、100=吸附；状态是上次指令，不是真空或抓取成功传感器 |
| 频率 | 25 Hz，即每秒 25 帧 |

手机的平移、固定参考末端朝向、J6 直接转动和 A/B 吸盘保持原逻辑。新旧入口共用原有手机伺服发送及重试代码，不再增加固定 J5 或 2°目标差检查。逆解错误、非有限指令、控制器发送和吸盘 IO 失败仍会中止。

按 `r` 复用旧归位流程，常规起点为 `[-65.29, -5.88, 113.77, 31.07, 90.88, -185.32]°`，到位后释放。人工确认路径无障碍；软件工作空间边界不是碰撞检测。

TCP（工具中心点位姿）仍只用于手机遥操内部逆运动学，不进入模型。标签记录控制器接受的六关节绝对目标及吸盘指令，不是用实测角度代替目标；SDK 发送单位为弧度，数据单位为度。

## 使用步骤

先在仓库根目录查看方案，以下命令不会连接设备或创建数据目录：

```bash
.venv/bin/python examples/phone_to_auboi10/record_joint.py \
  --dataset-root datasets/aubo_joint_legacy_smoke_001 \
  --evidence-root artifacts/aubo_joint_legacy_smoke_001 \
  --num-episodes 1 --split train
```

准备好机械臂、相机、手机和现场操作条件后，人工运行相同命令并在末尾加 `--record` 才会连接设备、允许归位与遥操作。每条填写场景编号和物理刻度线参考；按 `r` 归位，再按右箭头开始；录制中右箭头结束、左箭头重录、Esc 停止。录完填写单根成功、抓空、多抓、滑落、受阻或不确定。

填写场景、摆放参考及结果时，快捷键监听暂停，避免与文字输入争抢键盘；填完场景信息后恢复快捷键。正常或异常退出时，入口先尝试关闭伺服，再整理视频文件；关闭失败会报错提示，不能把文件保存完成当成机械臂已经安全停止。Esc 不是硬件急停，也不能中断正在等待完成的归位运动。

一条录完后只读检查：

```bash
.venv/bin/python examples/phone_to_auboi10/audit_joint_dataset.py \
  --dataset-root datasets/aubo_joint_legacy_smoke_001 \
  --evidence-root artifacts/aubo_joint_legacy_smoke_001 --require-gripper-quality
```

审计核对数据结构、动作发送证据、时间戳及保存状态；不解码视频，不证明物理抓取成功。还需人工看两路视频、核对吸盘时序和实际抓放结果。退出或失败的尝试保留在记录中；未满计划条数时 `capture_complete=false`。

`audit_passed` 只说明记录一致。`gripper_quality_passed` 另外检查吸盘统计是否覆盖 0/100，以及标为成功的示范有没有完整开启和释放。加 `--require-gripper-quality` 后，不满足这些条件会返回非零退出码。必须在录制中完成释放，再结束该条；结束后归位时释放不会成为训练标签。质量通过也不代表模型一定学会。

一条验证通过后，再使用全新目录、`--num-episodes 60 --split train` 录制训练集。另录验证场景，使用另外的目录和 `--split validation`。同一摆放场景不要跨训练、验证和测试；入口记录场景编号，跨数据集划分仍需后续统一检查。失败示范保留结果标签，后续监督微调不能不加筛选地模仿失败动作。

## 训练与研究边界

`make_joint_smolvla_config()`、处理器、审计及独立训练入口已同步为七维，预测 50 步，`n_action_steps=1`。吸盘为索引 6；归一化只使用选中的成功训练示范。旧六维固定 J5 契约会被拒绝，旧 13 维状态/8 维 TCP 数据也不混用。

当前只完成离线模拟控制器和真实文件往返、处理器以及替身训练测试。GPU 机仍是此前六维版本，未部署此次修改、未验证七维真实模型，也没有启动正式训练或接通在线策略执行。旧 `train.py`、`inference_server.py` 仍为 ACT 入口。

[SmolVLA 官方文档](https://huggingface.co/docs/lerobot/smolvla)建议约 50 条示范作为起点，并让各场景变化都有多次示范；这不是成功保证。[论文](https://arxiv.org/abs/2506.01844)的跨平台适配不能替代本项目的动作契约验证。当前不能把过去训练失败全部归因于 TCP 或数据少。

后续顺序：确认新数据链路 → 50 条以上高质量示范及独立验证 → 监督微调与离线误差检查 → 受控真机评价。基础抓取形成后，再按两份研究备忘录讨论分离进展/动作后果建模和潜在空间强化学习。文档中的研究建议不是已验证结果，也不是硬件执行指令。
