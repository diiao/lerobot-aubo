# AUBO i10：固定第五轴的关节示范采集

这条新路线使用 `record_joint.py`，旧 C0/TCP 入口及历史数据保留。修改前的代码存档为 `c216081`。新入口尚未完成真机采集验证；不要直接投入整批录制。

## 模型到底学习什么

| 项目 | 定义 |
| --- | --- |
| 图像输入 | CameraSetV2 的 global_rgb、grasp_rgb，两路 RGB |
| 数值状态输入 | J1、J2、J3、J4、J6、gripper_pos，共 6 维 |
| 动作输出 | 上述五个关节的绝对目标角度，以及吸盘指令，共 6 维 |
| 第五轴 | 控制层补入 J5=90°，不由模型预测 |
| 单位 | 数据中的关节角度为度；发送给 AUBO SDK 时转换为弧度一次 |
| 吸盘 | 0=释放、100=吸附；状态是上次指令，不是真空或抓取成功传感器 |
| 频率 | 25 Hz，即每秒 25 帧 |

第五轴实测值偏离 90° 超过 0.5°时拒绝继续；0.5°是测量容差，命令始终是 90°。新入口归位时将旧起点的 J5=90.88° 改为 90°，其余起点关节不变，旧起点文件不变。归位仍需要人工确认路径无障碍，软件关节限位不是碰撞检测。

TCP（工具中心点位姿）不进入新模型。手机仍通过末端运动遥操作，IK（逆运动学，即将末端目标换算成关节目标）在生成训练标签之前完成。若 IK 要求的第五轴偏离过大，入口会拒绝该动作，不能强行覆盖后继续运动。首次真机验证需确认固定 J5 时手机平移及 J6 转动范围可用。

录制标签是控制器接受的目标关节指令，不是当前或下一帧的实测角度。记录时核对标签、发送值和 SDK 目标，失败不保存为成功示范。关节限位从控制器读取，单周期目标变化和目标相对当前角度均限制为 2°，超限拒绝，不截断后继续。

## 使用步骤

先在仓库根目录查看方案，以下命令不会连接设备或创建数据目录：

```bash
.venv/bin/python examples/phone_to_auboi10/record_joint.py \
  --dataset-root datasets/aubo_joint_j5_smoke_01 \
  --evidence-root artifacts/aubo_joint_j5_smoke_01 \
  --num-episodes 1 --split train
```

准备好机械臂、相机、手机和现场操作条件后，人工运行相同命令并在末尾加 `--record` 才会连接设备、允许归位与遥操作。每条填写场景编号和物理刻度线参考；按 `r` 归位，再按右箭头开始；录制中右箭头结束、左箭头重录、Esc 停止。录完填写单根成功、抓空、多抓、滑落、受阻或不确定。

一条录完后只读检查：

```bash
.venv/bin/python examples/phone_to_auboi10/audit_joint_dataset.py \
  --dataset-root datasets/aubo_joint_j5_smoke_01 \
  --evidence-root artifacts/aubo_joint_j5_smoke_01
```

审计核对数据结构、动作发送证据、时间戳及保存状态；不解码视频，不证明物理抓取成功。还需人工看两路视频、核对吸盘时序和第五轴实际姿态。退出或失败的尝试保留在记录中；未满计划条数时 `capture_complete=false`。

一条验证通过后，再使用全新目录、`--num-episodes 60 --split train` 录制训练集。另录验证场景，使用另外的目录和 `--split validation`。同一摆放场景不要跨训练、验证和测试；入口记录场景编号，跨数据集划分仍需后续统一检查。失败示范保留结果标签，后续监督微调不能不加筛选地模仿失败动作。

## 训练与研究边界

`make_joint_smolvla_config()` 提供显式 6 维状态/动作及双 RGB 配置，`SmolVLAJointOfflineAdapter` 只用于离线预测。训练时需基于新训练集重新计算归一化统计，并随模型保存 `AuboI10JointFixedJ5V1` 契约。即使 SO100 模型也是 6 维，关节含义仍不同，不能直接拿其微调权重及统计量控制 AUBO。

旧 13 维状态、8 维 TCP 动作数据不直接混入；旧 relative_xyz（相对位置）处理、旧吸盘索引和 TCP 执行接口不适用于此入口。新代码没有接通自动策略执行，也没有启动训练。真实 SmolVLA 权重集成仍需要具备模型依赖的环境验证。

[SmolVLA 官方文档](https://huggingface.co/docs/lerobot/smolvla)建议约 50 条示范作为起点，并让各场景变化都有多次示范；这不是成功保证。[论文](https://arxiv.org/abs/2506.01844)的跨平台适配不能替代本项目的动作契约验证。当前不能把过去训练失败全部归因于 TCP 或数据少。

后续顺序：确认新数据链路 → 50 条以上高质量示范及独立验证 → 监督微调与离线误差检查 → 受控真机评价。基础抓取形成后，再按两份研究备忘录讨论分离进展/动作后果建模和潜在空间强化学习。文档中的研究建议不是已验证结果，也不是硬件执行指令。
