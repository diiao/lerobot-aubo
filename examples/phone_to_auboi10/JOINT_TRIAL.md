# 七维 SmolVLA 首步现场检查

本入口仅用于 `AuboI10JointLegacyTeleopV2` 当前检查点的现场只读预测和一次小幅关节命令，另有独立 `home` 起点准备阶段。它不是完整抓放程序，也不替换手机遥操、采集或旧 ACT 服务。

`run_joint_trial.py` 默认 `plan`：不导入硬件 SDK，不加载模型，不连接设备。`shadow` 接收真实双 RGB 和七维状态，输出预测及拒绝原因，绝不获取 `MotionControl` 或调用数字输出写入方法。由于 SDK 将数字输出读取与写入方法放在同一 `IoControl` 对象，本入口用该对象的两个 getter 读取输出 2/3；不能声称它完全没有取得该 SDK 对象。读回仅代表控制器输出，不是物理真空反馈。

`single-step` 需要最近 120 秒内、同一模型、CameraSet 及试验参数的 shadow 报告，以及现场确认参数和本次新观测重新通过检查。默认时序要求 12 帧全部通过；显式静态单步要求完整完成 12 帧预览且至少一帧通过。后者只证明存在满足首步边界的预测，不代表模型全部通过。只发送动作块第一步，度转弧度仅在发送边界进行；不执行整个 50 步动作块。当前第一步验证未通过时不能跳到此模式。

## 首步边界

- 只允许在既有起点附近：`[-65.29,-5.88,113.77,31.07,90.88,-185.32]` 度，各关节起始及目标偏差不超过 0.5 度。
- 单步目标相对当前实测关节不超过 0.2 度，命令时间 0.04 秒，等效关节指令速度不超过 5 度/秒。
- 目标 TCP 与当前 TCP 距离不超过 2 毫米，等效速度不超过 0.05 米/秒；先验证当前 SDK 正运动学结果与实测 TCP 一致，防止工具坐标含义不符。
- 使用控制器实际关节上下限，不从训练数据推断安全范围；不裁剪或角度绕回。
- 最老输入帧到检查时刻不超过 100 毫秒，两相机时间差不超过 50 毫秒；再次读取当前状态也必须新鲜。
- 只允许机器人静止、正常安全状态、吸盘关闭，且模型也预测保持关闭。不改写吸盘目标来强行通过检查。
- 不设置全局速度比例，不自动回起点，不重试错误码，不自动恢复伺服，不写吸盘 IO。已有伺服开启时拒绝接管。
- 伺服开启后再次检查；成功命令等待命令时长（默认 0.04 秒，显式静态模式 0.2 秒）后关闭伺服并确认。模式切换后按既有驱动最多等待 5 次、每次 5 ms，只轮询状态，不重复发送命令。发送失败、SIGINT/SIGTERM 或其他异常也走关闭路径。硬件断电、进程被 SIGKILL、SDK 或控制器失效时，软件清理不可能提供保证，现场实体急停仍是独立保护。

这组保守边界只服务于首个单步试验，不能作为完整抓放控制参数，也不构成全机械臂碰撞证明。后续连续执行需要另外验证节拍、独立停止/看门狗及持物情况下的故障处理；当前入口不提供完整抓放模式。

### 显式静态单步模式

`--stationary-step` 单独用于机械臂和竹条静止、操作者在场的单步实验，不用于连续执行。相机帧在采集时仍需满足 100 ms 新鲜度，等待预测上限为 250 ms；执行前重新读取当前状态，六关节相对预测输入变化不得超过 0.02°，吸盘状态必须相同。最老观测的真实年龄仍完整记录，不修改或补写时间戳。

该模式将“采集帧是否陈旧”和“静止期间等待计算”分开，是显式改变试验时序语义，不是原100 ms端到端门控已经通过。静态单步命令时间单独设为 0.2 秒，保持 5°/s 和 0.05 m/s 的指令速度上限，对应最大相对位移 1° 和 10 mm；当前及目标距起点各轴不超过 0.5°的边界不变。默认时序仍为 0.04 秒、0.2°、2 mm。关节限位及停止行为不变。旧模式和已有报告保留，现场/单步报告必须使用同一时序模式。250 ms是本次静态实验的等待预算，不是通用机器人安全标准。

### 独立归位

`--stage home` 不加载模型、不打开相机，只使用既有 NORMAL_START_DEG。仅当吸盘关闭、机器人静止、无已有伺服控制者且当前和目标关节都在控制器限位内时允许执行。已移除首步试验遗留的10°归位距离限制；这是完整moveJoint归位轨迹，不是模型单步动作。moveJoint 参数与 move_to_start.py 一致，采用80°/s²加速度、60°/s速度及50%全局速度比例；停止后恢复归位前读取的速度比例，避免影响后续推理。归位等待时间为 max(30秒, 最大关节距离/30°每秒 + 15秒)，超时、异常或中断时请求stopJoint（80°/s²），不重试。若2秒内仍未确认静止，不恢复全局比例并报告错误。操作员须确认关节归位路径无遮挡；本入口不生成避障路径。到位要求各轴误差不超过0.1°且控制器报告静止。不写吸盘输出，所以它只复用r归位的目标，不包含旧r的自动释放动作。

## 推理链路

`joint_inference_stdio.py` 在 GPU 机独立 artifacts 目录运行，通过 SSH 标准输入/输出传输 JSON；无外网监听端口，无 pickle 反序列化。当前传输使用 JPEG 质量 95，编码前 RGB→BGR、解码后 BGR→RGB，保留训练颜色约定。JPEG 有损，不能声称与无损输入逐值等价。原 `rgb_zlib` 编码保留用于离线对比。服务先确认 GPU 无计算进程，验证权重 SHA-256、七维契约和严格加载，再做两次合成预热；不更新权重。工作站收到 ready 后才连接现场设备。

保存现场图片的五组固定随机种子对比中，无损请求约 296～344 ms，JPEG 请求约 136～150 ms；JPEG 造成的最大关节预测差异约 0.100°，五组吸盘判断一致。这只覆盖一个静止现场画面，不证明抓放切换表现不受影响。快速矩阵计算另做了对比，收益较小，正式入口默认不启用。模型权重、10 步采样、动作语义和控制检查未变。当前请求仍未满足原 100 ms 端到端时效检查；静态模式以单独声明的时序条件进行验证，不能据此宣称连续控制通过。现场已完成独立低速归位，其记录在 home_run01；后续动作以对应现场输出目录为准。

后续离线检查：BF16收益很小，未启用；CUDA Graph在当前视觉编码器的mask搬运处不兼容，未采用，也未修改模型内部代码。默认现场推理仍为原精度、原采样步数。

现场来源、相机快照、模型哈希、原始预测、解码动作、时戳、门控拒绝原因和运行结果都保存在独立输出目录。服务随本次 SSH 输入 EOF 退出，不操作其他服务或进程。

现场操作者明确启动的归位与静态只读检查：


## 短段闭环试验

`--stage short-loop --stationary-step` 最多执行 3 次独立小步，每次重新读取双相机和实测关节，只取新预测的第一步。需要近期 `--stage short-shadow --stationary-step` 的完整只读预览，报告参数必须一致。短段专用起点范围为各轴 ±1.5°（三倍原单步范围），最多 3 步；每步仍为 0.2 秒、最大 1°/10 mm、指令速度上限 5°/s 和 0.05 m/s。原单步 ±0.5°范围保留，不裁剪输出、不改吸盘预测。它是“停稳后重新观测”的低频闭环，不是 25 Hz 连续伺服。

每步关闭伺服后最多等 1 秒确认控制器静止；下一次观测要求相机时间戳晚于停稳确认。任一步超时、越界、预测吸盘开启或 SDK 异常即结束，不重抽预测、不自动归位。按步保留 trace、输入图像、发送回执和停稳后的实测位置；本阶段不写吸盘 IO，不能验证物理抓取。入口停用即可回退至原流程。

先前从单步结束位置进行的 `short_loop_shadow_run01` 在原 ±0.5°首步范围下 12 次均被拒绝，尚未发动作；由此明确区分首步验证与三步累计运动范围，未把旧报告改写为通过。

`short_loop_shadow_run02` 在短段专用范围下 12/12 通过；`short_loop_run01` 实际完成 3 步，每步新观测、新预测、停止及伺服关闭回执完整。各轴累计变化约 `[0.8463,0.7836,0.1525,-0.5971,-0.0220,-0.3627]°`，最大目标误差 0.0462°。最后实测 TCP 相对上一轮 settled_readback 净变化 `[8.10,6.59,6.66] mm`，距离 12.39 mm；参考起始 TCP 来自上一轮静止读回，本轮第一帧关节与该记录一致。50 项测试通过。吸盘始终关闭。图像尚不足以确认持续接近竹条，完整抓放和 25 Hz 连续控制仍未验证。详见该目录 `verified_result.json`、逐步回执与图像。

## 持续伺服入口（替代逐步停稳试验）

`run_joint_smooth.py --execute` 保留手动任务输入和开始确认，由操作者启动。旧 `run_joint_live.py` 保留用于回退。默认不带 --execute 仅打印计划，不访问硬件。

模型仍预测第一步绝对关节目标，后台单个线程负责推理与低频存图；本地主线程独占机器人 RPC，以 25 Hz 更新关节参考位置。每轮只开启一次伺服，结束、超时、异常或 Ctrl+C 时关闭。采用带速度/加速度限制的位置跟踪生成中间点，原始模型目标记录在 trace，实际命令和速度记录在 commands。它改变了执行轨迹，不是模型原始动作逐值重放。

更新后模型目标取消相对当前状态 3°/50 mm 距离门限，仍检查数值有效、SDK关节限位和采集工作区；目标不会直接发送，而由轨迹生成器逐渐接近。3°仅用于实际发送中间位置与实测关节的跟踪误差检查，防止执行器停滞时参考轨迹持续跑远。中间命令仍限制各轴 5°/s、20°/s²及 TCP 50 mm/s。TCP 限速无法同时满足加速度限制时拒绝，SDK 非零返回不重试。25 Hz 是目标发送频率而非操作系统硬实时保证；控制循环间隔超350 ms停止，普通运动600 ms没有新鲜预测停止，期限从最近接受预测的最早输入观测时间计算。每次接受的预测输入年龄不超过400 ms（为容纳远程请求延迟波动，由300 ms调整）。不再要求运动期间状态不变。

TCP 限速介入时，不再将期望关节速度直接向零缩放，以免让已经达到减速度上限的轴再次减速。平滑器先从上一周期速度构造本周期可达的减速速度，再与期望速度混合，进行6次有界搜索；每个候选点都通过正运动学检查末端位移。关节速度、加速度及末端速度门限不变。减速候选不满足末端限速时仍拒绝，且不更新轨迹状态；此搜索不保证找到所有可能的可行解。常规周期调用2次正运动学，限速周期最多9次，因此真机控制周期耗时仍需现场验证。

吸盘不做平均或平滑。模型要求切换时暂时保持该关节目标，待实测关节距目标小于0.15°且参考速度小于0.3°/s，再调用原驱动的IO写入和读回，最多等待目标1.5秒。该过程短暂停止更新模型目标；IO读回可能产生短暂停顿。完成后重新采集、预测。异常退出不自动释放持物。回执仅证明控制器输出，物理抓取仍由现场观察判断。

单轮最多120秒；完成模型开启/释放周期后结束。模型权重和任务不变。持续伺服关闭确认允许等待1秒，只轮询状态，不重复发送关闭命令；原单步入口默认25ms等待保持不变。上一版持续伺服已由用户现场运行约22.9秒、571帧，用户反馈连贯，末次J6模型目标约3.2°超限退出。此次目标距离门限调整及关闭确认等待尚未实机执行。日志中的角速度/加速度上限指发送参考轨迹，不是已测得的物理运动上限。

## 推理期间双相机录像

持续伺服入口默认启用录像，不增加命令参数。操作员确认开始后启动录像，机械臂停止后收尾，最后断开相机。输出：

- `videos/global_rgb.mp4`：全局相机，640×480，25 fps，H.264。
- `videos/grasp_rgb.mp4`：抓取相机，相同格式。
- `videos/*_frames.jsonl`：每个输出帧的采集时间、视频时间、重复来源及补帧标记。
- `videos/complete.json`：帧数、重复帧、队列丢帧、读帧失败及编码错误。

录像读取已有OpenCV采集线程的最新RGB帧，不重新打开设备、不改变30/25 fps相机配置。单独采样线程以25 Hz采样，两路各有8帧有界队列和独立FFmpeg编码线程/进程，每路编码限一个线程；伺服线程不编码、不写视频管道。编码跟不上时丢弃新入队帧，后续以重复帧补齐视频时间轴，实际源时间保存在旁路记录。因此这是25 fps现场记录，但不保证每帧都来自独立曝光，也不保证无丢帧。录像错误独立写入报告和结束提示，不伪报录像成功。
