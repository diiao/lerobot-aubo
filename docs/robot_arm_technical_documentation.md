## 1. 阶段目标

本阶段的任务是让 AUBO i10 在两路视觉和自身状态的条件下，以**纯 ACT** 输出完成：

```text
常规初始位 -> 接近竹条 -> 下探 -> 吸附 -> 抬升并搬运 -> 目标区放置 -> 释放
```

早期 30 条基线模型（run05）已验证从数据到机械臂控制的链路可用，但真实闭环中一旦末端悬在竹条上方、错过下探阶段，模型容易持续悬停，难以回到示教中常见的状态。本阶段的核心目标不是写一段固定的下降或抓取脚本来掩盖这个问题，而是补充这类偏离状态的人工示教，让 ACT 学习恢复动作。

## 2. 方法与系统架构

### 2.1 纯 ACT 策略

ACT（Action Chunking with Transformers）一次预测一段未来动作，而非只预测单一控制量。当前模型是标准 ACT 的 CVAE 版本：

- 输入：13 维机器人状态、`handeye` 与 `fixed` 两路 640×480 图像；
- 输出：8 维绝对末端动作：`ee.j6_target`、末端 xyz、旋转向量 wx/wy/wz 与持续的吸盘状态 `ee.gripper_pos`；
- 训练动作块：25 帧，即约 1 秒；
- 训练控制频率：25 FPS；
- 视觉骨干：ImageNet 预训练 ResNet-18；
- CVAE：启用，潜变量 32 维，KL 权重 10；
- Transformer：512 维、8 头、4 层编码器、1 层解码器。

模型输出不经过“竹条在这里就下降”之类的任务专用规则。机器人端仅保留与任务无关的安全措施：工作空间边界、单帧位移限幅和 AUBO 所需的 `abs_j6yaw` 控制模式。

### 2.2 分体式部署

```text
工作站：相机 + AUBO i10 + evaluate_split.py
      -> Tailscale TCP (100.88.143.45:5555)
GPU 机：inference_server.py + run06 ACT checkpoint
      -> 返回当前动作
工作站：通用安全处理 -> servoCartesian / 吸盘 IO
```

GPU 机不直接连接相机或机械臂。模型与现场硬件解耦后，GPU 只负责推理，工作站负责实时观测和安全执行。

## 3. 数据设计：从“理想成功轨迹”补到“闭环恢复轨迹”

### 3.1 两类起点

为避免把两种状态混为一谈，项目保留两个明确的关节起点：

| 类型 | J1–J6（度） | 用途 |
|---|---|---|
| 常规起点 | `[-65.29, -5.88, 113.77, 31.07, 90.88, -185.32]` | 常规录制、常规推理和 `r` 自动归位 |
| 恢复起点 | `[-23.27, -5.91, 111.13, 28.57, 89.55, -162.21]` | 代表 run05 真实闭环失败时竹条上方的悬停状态 |

恢复起点不是新的默认推理起点。它仅用于录制完整的“下降—吸取—抬升—放置—释放”恢复示教，防止在真实推理过程中混入手机人工接管。

### 3.2 聚合数据集

训练数据集 `bamboo_newview_full_recovery_v1` 由两部分构成：

| 数据组成 | Episodes | Frames | 作用 |
|---|---:|---:|---|
| s01–s04 常规成功示教 | 30 | 26,939 | 学习完整常规任务 |
| s05–s06 恢复示教 | 30 | 24,858 | 学习从竹条上方悬停状态继续完成任务 |
| 合计 | **60** | **51,797** | run06 的训练集 |

聚合前已检查 episode/frame 连续性、两路视频帧数、动作 NaN、吸盘 `0/100` 标签以及末端动作跳变。重录或中断的临时数据没有写入聚合 metadata。

## 4. 工程改动与优化

| 改动 | 解决的问题 | 工程原则 |
|---|---|---|
| `aubo_start_poses.py` | 统一常规与恢复起点，避免多个脚本各自维护角度而漂移 | 单一事实来源 |
| `move_to_recovery_start.py` | 从常规起点 ±5° 内才允许进入恢复位，且以低速运动 | 降低未知姿态下关节运动风险 |
| `record.py` 的 recovery 模式 | 每条恢复示教按 `r` 自动执行“常规位 -> 恢复位 -> 释放吸盘” | 每条数据起点一致，不依赖操作者目测高度 |
| `record.py` 重录流程 | 左箭头重录时清空当前 episode 缓冲区 | 失败轨迹不混入训练集 |
| `audit_act_offline.py` | 把保存观测送入 checkpoint，逐维检查动作、吸盘、抓取高度和跳变 | 离线验收不连接任何硬件 |
| `inference_server.py` | 修复 ACT CVAE 在无 action 推理时错误走编码器的问题 | 推理与训练的 CVAE 路径一致 |
| temporal ensembling | 对每一控制帧的重叠 ACT 动作块做时间融合，当前系数 0.01 | 减少动作块边界跳变 |
| `evaluate_split.py` 的 8 mm 限幅 | 拦截离群模型输出造成的瞬时大位移 | 通用安全约束，不使用竹条位置规则 |

相关 Git 提交：`16e2f18`、`545b53f`、`ec69436`、`87548ce`。推理服务实际以 `TEMPORAL_ENSEMBLE_COEFF=0.01` 启动；这会将运行时 `n_action_steps` 设为 1，并保留模型本身 25 帧动作块的预测能力。

## 5. 训练设置与模型选择

训练在 GPU 隔离工作树 `/home/rentao/program/lerobot-aubo-pure-act` 上从头运行 30,000 steps：

```text
模型目录：models/bamboo_newview_act_run06_recovery
最佳 checkpoint：best/
最佳 validation loss：0.13953（step 29,000）
最终 validation loss：0.14420
```

因此部署和评估均使用 `best/`，而不是训练结束时根目录的最终权重。验证集按完整 episode 取最后 20%，即 episode 46–59；该部分恰好属于 s06 恢复数据。因此 run06 的 loss 不应与 run05 的 loss 直接横向比较。

## 6. 离线模型验收

离线审计使用保存的数据观测进行 teacher-forced 回放：它能检验模型输出是否合理，但不能替代真实闭环成功率。结果如下。

| 数据段 | XYZ MAE（mm） | 吸盘 precision / recall | 抓取高度 MAE |
|---|---|---|---:|
| 常规起点 30 条 | 4.55 / 2.55 / 1.28 | 99.66% / 98.91% | 2.49 mm |
| s05 恢复 16 条 | 2.87 / 2.10 / 1.43 | 99.60% / 99.28% | 1.92 mm |
| s06 恢复 14 条（保留集） | 4.20 / 2.67 / 1.80 | 99.18% / 99.26% | 2.71 mm |

附加检查显示：

- 即使把输入状态中的吸盘读数强制设为释放，模型仍能以 95.8%–97.5% 的召回率主动开启吸盘；
- 在审计的队列执行模拟中，60 条轨迹均没有超过 3 cm 的单帧 XYZ 跳变；
- s06 存在少量末端绕 Z 轴角度误差较大的帧（最高约 0.68 rad）。它不改变吸盘法向的主要 xyz 抓取精度，但后续应通过更一致的手腕姿态示教继续减小该误差。

## 7. 真实推理验证：run06 trial01

2026-08-03 进行了 1 次常规起点的真实推理。模型从 GPU 机服务端加载 `run06_recovery/best`，并启用 temporal ensembling（0.01）。评估数据集为 `bamboo_newview_eval_run06_trial01`。

| 检查项 | 结果 |
|---|---|
| 保存数据 | 1 episode，1,491 帧，59.60 秒，25 FPS；两路视频完整 |
| 数据完整性 | frame/timestamp 连续，无 NaN |
| 吸盘时序 | 第 18.64 秒开启，第 42.16 秒释放，持续约 23.5 秒 |
| 轨迹平滑性 | XYZ 单帧最大变化为 3.12 / 2.86 / 1.42 mm；零帧超过 8 mm |
| 放置后稳定性 | 释放后约 17.4 秒内，末端 xyz 最大波动 3.28 mm |
| 现场与视频结论 | 竹条从抓取区被带到目标放置区并完成释放；本次任务成功 |

这证明当前场景与常规起点下的端到端流程可行，但只构成 **1/1 的单次成功证据**。要报告成功率，需要预先定义抓取、搬运和放置成功标准，并在独立重复试验中统计结果。

## 9. 论文写作可用的表述边界

可以表述为：本阶段通过加入来自真实闭环偏离状态的恢复示教、保持纯 ACT 控制输出，并结合时间集成与通用安全约束，实现了从常规起点到抓取、搬运和放置的真实机械臂单次端到端成功验证。

暂不应表述为：模型已在不同竹条长度、不同位置、不同光照或大量独立试验下达到稳定泛化成功率；模型也尚未获得竹条中点等显式几何监督。

下一阶段若要写成更强的实验结论，应固定评价协议并至少报告：试验次数、抓取成功率、放置成功率、平均完成时间、竹条位置/长度扰动范围，以及失败类型统计。
