# AUBO i10 竹条逐层分离：上层实例分割与目标条件化抓放

创建：2026-09-26。研究结论更新：2026-10-02。

状态：已记录本轮方案取舍，尚未实施或验证新路线。当前推荐优先验证**全局 RGB 上层竹条实例分割＋目标条件化 SmolVLA 单次抓放**，暂缓 Qwen/VLM 部署，将现成 VLM 保留为可选对照，强化学习暂不作为第一阶段工作。本次更新只保存研究结论，不启动采集、训练、推理或机器人执行。

保留原文件名以兼容现有链接。第 1～8 节是当前研究依据；后面的 H1～H4 保留旧 VLM/RL 方案及现有评价器说明。两者不一致时，以当前研究依据为准；代码是否具备某项能力仍以实际实现为准。

## 1. 目标、现场条件与现有能力

- **任务范围：**三根及以上竹条在桌面工作区自然摆放、交叉堆叠。每次取走一根上层竹条，放入收集区，确认结果后重新观察，直到清空。先研究可以逐根移除的堆叠，不包含必须主动拨开、抽出或解缠的场景。
- **上层定义：**没有被其他竹条压住的一根；不是图像中位置最高的像素，也不是露出面积最大的一根。最上层可以有多根，任选一根正确上层即可，第一版不做复杂的抓取难度或最优顺序排序。
- **相机分工：**用户确认固定全局相机能看清整个料堆及交叉关系；腕部相机视野较小，不适合整堆标注。视觉选择先只用 `global_rgb`，腕部 `grasp_rgb` 继续用于局部动作观察。目前没有增加第三台 RGB 相机的必要依据。
- **工程基础：**现有 CameraSetV2 双 RGB、七维状态和动作 `[J1,J2,J3,J4,J5,J6,gripper_pos]` 保留。当前模型训练 160 条、验证 22 条；单根及两种熟悉双根摆放已有成功反馈，未建立未知堆叠泛化成功率，见[当前证据索引](../examples/phone_to_auboi10/EVIDENCE.md)。
- **尚未具备：**当前 [SmolVLA 适配器](../src/lerobot/bamboo_sorting/smolvla_joint_adapter.py)没有目标点、目标掩码或 `goal_image` 输入；混训运行入口仍固定两个周期，单次任务接口和自动清空判断需要后续实现。不能把研究设计当成可直接使用的命令。

递归思想在程序中可以用循环实现：`观察 → 选上层 → 抓放一根 → 确认结果 → 重新观察`。成功移除一根后，剩余场景仍是同一类问题；失败或邻条位移时，不能沿用初始场景一次性排好的顺序。现场人员承担操作监督；照片不可判定仍需如实记录，不能把现场知道的答案当成图像已提供的证据。

## 2. 方法比较与本轮取舍

实例分割是为每个物体输出独立的像素区域，称为 `mask`（掩码）。细长竹条的矩形检测框容易同时包含其他竹条，掩码能更明确地表达选中了哪根。

| 方法 | 输入与输出 | 数据或额外条件 | 判断 |
| --- | --- | --- | --- |
| 直接分割上层竹条 | 全局 RGB → 各个上层实例的掩码和分数 | 上层轮廓标签、专用模型微调 | 优先验证；不要求恢复下层完整形状和全部关系。主要风险是把下层露出片段识别为上层，或合并相邻竹条。 |
| 实例分割＋成对关系预测 | RGB → 全部可识别竹条实例 → 谁压谁 → 上层候选 | 所有实例及相关交叉关系标签 | 备用；错误可定位到具体关系，但遮挡下的身份关联和标注成本更高。 |
| 真实深度＋三维抓取 | RGB-D/点云 → 高度、表面方向、吸附候选 | 可用深度、相机与机械臂标定、执行接口 | 不作为当前双 RGB 路线的直接替换。薄竹条的层间高度是否可测必须验证。 |
| 直接预测抓放位置 | 图像/高度图 → 抓取和放置位置 | 抓放动作标签及坐标转换 | 可研究，但会改变现有执行链路；静态层序标签不足以训练完整抓放动作。 |
| 传统图像方法 | 边缘、轮廓、交叉连续性 → 上下判断 | 稳定背景、成像和规则开发 | 作为简单对照；平行、近重合边界、阴影和纹理相似会增加规则失效。 |
| 现成视觉语言模型（VLM） | 图片＋问题 → 目标或关系答案 | 任务评估标签；自动定位能力需另测 | 保留为可选对照；不能仅依据通用空间能力或可部署性认定适合竹条任务。 |

研究与实现依据（本轮于 2026-10-02 查阅）：

- [Mech-Mind 官方实例分割案例](https://docs.mech-mind.net/en/dlk-software-manual/latest/algorithm-modules/instance-segmentation-example-projects.html)采用只标注最上层暴露物体的方法。该案例还包含可见抓取点和箱壁距离等条件；本项目借鉴直接学习上层区域的思路，标签按本项目上层定义制定，不照搬其他筛选条件或小样本效果。
- [VMRN 原始论文](https://arxiv.org/abs/1802.08857)研究 RGB 目标检测和操作关系预测；[作者实现](https://github.com/ZhangHanbo/Visual-Manipulation-Relationship-Network-Pytorch)依赖很老的 PyTorch，并记录了分支间性能差异，不作为现成部署组件直接引入。
- [UOAIS 官方实现](https://github.com/gist-ailab/uoais)预测可见区域、被遮挡的完整区域及遮挡状态，但其公开主要流程/检查点使用 RGB-D 或深度，不能假设在本项目单张 RGB 上直接复现。
- [Transporter 官方代码](https://github.com/google-research/ravens/blob/master/ravens/agents/transporter.py)从 RGB-D 生成颜色图和高度图，再把像素转成末端位姿。工作区位于桌面不意味着所有堆叠目标处于同一高度，不能以固定接触高度代替缺失信息。
- [SAM 2 官方说明](https://ai.meta.com/research/sam2/)提供点、框或掩码提示的分割能力，可辅助描边与纠错；它的分割输出不自动构成物理层序判断。

推荐直接上层分割，是因为当前目标只要求选择上层，而不是还原完整关系图。这是任务匹配和工程成本上的判断，尚不是本项目成功率结论。

## 3. 视觉模型与标注规范

### 3.1 第一版模型与输出

建议基线：`torchvision.models.detection.maskrcnn_resnet50_fpn`，即采用 ResNet-50-FPN 图像特征网络的 Mask R-CNN 实例分割模型。从预训练权重开始微调，把任务目标类别定义为 `top_strip`，背景为另一类。预训练权重本身并不会识别本项目定义的上层竹条，需要任务数据训练。

现成组件能完成掩码学习和预测；它能否在竹条上学会层序需要实测。实现依据为 [TorchVision 模型接口](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.detection.maskrcnn_resnet50_fpn.html)及[官方微调教程](https://docs.pytorch.org/tutorials/intermediate/torchvision_tutorial.html)。

```text
全局原始 RGB 图
  → 上层实例分割模型
  → 零个、一个或多个 top_strip 掩码及分数
  → 从达到开发集所定阈值的实例中选择分数最高的一根
  → 输出该根的目标掩码
```

分数是识别模型的支持程度，不是物理抓取成功率。没有检测结果表示本次没有识别到目标，不表示工作区已清空。多个上层都属于正确候选；数量增加后的迁移能力须单独评估，不能从三根结果自动外推。

### 3.2 人工标注

使用 Labelme 多边形工具作为第一轮标注方式：打开全局原图，沿每根确认上层竹条的可见轮廓分别画多边形，每个实例标为 `top_strip`，保存结构化标签。原图不覆盖，腕部图不要求整堆标注。SAM 辅助轮廓也必须人工修正。

1. **标全所有正确上层。**若 A、C 都压 B，且 A、C 互不遮挡，则 A、C 各标一个 `top_strip`。不能只标计划抓的一根，把另一根正确上层漏成负例。
2. **下层不标为目标。**确认的下层区域作为本任务的非目标背景，不需要补画其不可见完整形状。轮廓完整或露出面积大不能代替“没有被压住”。
3. **不确定图片分开保存。**层序或实例对应无法确认时，先放入不确定样本集合；不能简单漏标后进入普通监督训练，否则会制造错误负例。现场真相与从照片能否判断应分别记录。
4. **训练图与标签分离。**模型读取原始 RGB，掩码作为监督目标；不把涂有正确答案的图当作训练输入。
5. **A/B/C 点标签不等于分割标签。**旧 VLM 试验中的身份点和关系表可以保留作辅助，但本路线需要实例区域标签和数据转换程序，旧评价器也不会直接读取 Labelme 输出。

标注、训练与识别是不同步骤：`图片＋区域答案 → 微调 → 保存模型 → 新原图推理 → 独立真值评价`。保存标注文件不会自动改变模型能力。

## 4. 数据覆盖、分组与成本

采集重点是迫使模型依据关系判断的对照，而不是重复同一摆放：相近位置/角度交换上下层；45°和90°分别处于上层；一根压两根；链式交叉；多个独立上层；下层大部分露出但仍被压住；相似颜色纹理；近乎平行和边缘轻微交叠。还需覆盖单根、双根和空抓取区，因为清堆会经过这些状态。

可以人工逐根移除并拍摄 `三根 → 两根 → 单根 → 空场景`，减少为静态标签录制动作的成本。场景静止、手退出画面后保存全局图。同一初始摆放产生的照片、移除序列、相邻帧及增强图属于同一组，不能跨训练、验证和测试集合。

建议首轮预算为约 **150 个独立摆放组：80 组训练、20 组开发验证、50 组保留测试**。这是工作量建议，不是足够学会任务的承诺，也不表示已经采集或启动训练。每组可含多张衍生照片，因此组数不等于图片数。先试标训练/开发部分的 10～20 组，核对规则一致性、困难样本和实际耗时，再决定是否完成该预算；保留测试组不用于选阈值或调模型。

记录拍摄、标注、纠错和新增遥操作的总人时，才能验证是否真正节省人力。现有重复示教切分后能复用，但不会变成新的独立摆放。

[SynTable 研究](https://arxiv.org/abs/2307.07333)提供自动生成实例与遮挡标签的合成数据思路。合成图可辅助训练，但竹条材质、阴影、接触和弯曲的差异必须由真实照片测试；合成测试不能代替真实泛化评价。视觉增强需要同步变换图片和掩码，不能将相同旋转方法直接套到原有七维关节动作标签。

## 5. 连接 SmolVLA 的具体候选接口

这部分是**待验证设计**，不是现有能力。先验证动作模型服从人工给定的正确目标，再接自动分割。

| 项目 | 第一版候选设计 |
| --- | --- |
| 目标表达 | 在本轮开始的全局图副本上统一突出选中掩码，生成 `goal_image`（目标参考图）。 |
| 输入 | 当前全局图、当前腕部图、固定目标参考图、当前七维状态和任务文字。 |
| 输出 | 保持六关节及吸盘的七维动作，不增加固定高度或人为任务轨迹补偿。 |
| 更新时机 | 一次抓放期间保持参考图不变；确认本轮结果并重新观察后，才生成下一轮参考图。意外位移或失败不能盲目沿用旧目标继续下一轮。 |
| 训练样本 | 每段单次抓放都有段首目标参考图，配合后续实时双路图像、状态和实际示教动作。 |

`goal_image` 来自原全局照片，不需要第三台相机。固定参考图表达本轮选中的对象，实时双路图像表达执行中的当前状态；不能把段首掩码的位置直接当成后续每帧目标的实时坐标。

[SmolVLA 图像处理代码](../src/lerobot/policies/smolvla/modeling_smolvla.py)能遍历配置中的多个图像输入，但当前项目适配器约束为双路。落地需要扩展数据格式、适配器、预处理、训练及运行请求，并微调新模型；新增图像输入的延迟和显存也需测量。先在独立版本中验证，不覆盖现有双路模型和契约。

[MOO 官方项目](https://robot-moo.github.io/)提供目标视觉表示作为动作策略条件并通过示教训练的研究依据；上面的固定 `goal_image` 是本项目提出的适配方案，不是已复现 MOO，也没有在当前 SmolVLA 上验证。

已有单根/双根示教可检查并切分为单次抓放，补上段首目标标签；仍可能需要新增多目标指定抓取、位置和高度变化的示教。不能把抓 A 的动作改标为目标 B。仅换文字、给旧模型临时涂色或遮去其他竹条，都不能证明建立了目标条件化能力。

## 6. 执行闭环、结果与停止

```text
读取全局场景 → 识别并选定一根上层 → 生成目标参考图
  → 目标条件化策略执行一次抓放
  → 核对是否抓对、是否恰好一根、是否送达
  → 重新观察：继续选择 / 人工复核 / 确认清空后结束
```

第一轮由现场人员记录实际结果。每次只执行一个抓放周期是待实现的单次任务接口；现有混训入口固定两个周期，不能把此流程当成已有功能。吸盘 DO 读回及周期数只证明控制过程，不证明实际抓到或清空。

自动清空阶段需独立验证抓取区的“空／非空”判断，覆盖机械臂遮挡、漏检、光照变化，并区分抓取区与收集区。先报告“人工确认结果的逐层抓取”，再报告经验证的“自动确认结果与停止”，不能混称为完全自主清空。

## 7. 尽早验证与 GO/NO-GO 条件

这里的 GO 只表示值得进入下一项研究，不构成真实抓取可靠性或无人值守部署结论。

| 顺序 | 要回答的问题与检查 | 继续条件 / 失败处理 |
| --- | --- | --- |
| 1. 标注可判定性 | 用约 20 组原图检查不同标注者能否按同一定义指出上层并画出区域。 | 规则一致且关键交叉可判，再扩展标注。若人也看不清，先处理成像或任务范围，不靠加训练步数弥补。 |
| 2. 人工指定目标执行 | 建立目标接口并微调后，用两根都可取的场景，成对测试指定不同目标；保留与原模型的对照。 | 必须验证实际取走对象随提示改变；若总抓固定位置/角度，先修动作条件化，暂缓扩大视觉数据。离线动作数值变化本身不算通过。 |
| 3. 自动上层分割 | 保留 50 个独立测试组，预先指定每组一张非空关键图用于上层选择评分；其余帧、空场景分项报告。 | 建议探索门槛：至少 45/50 正确选择，剩余允许无输出，选中下层为 0。此门槛是研究建议，不能由小样本零错误推出高可靠性。 |
| 4. 逐根清空 | 合并自动视觉与单次动作，每抓后重新观察，覆盖三根到空场景。 | 分别报告目标选择、单根抓放、整堆完成和停止结果；失败按视觉、动作或结果判断定位，不用总体成功率掩盖。 |

第 2 项与小规模视觉训练应在同一轮早期验证，不能等全部分割训练结束才检查动作接口。三根验证后，再预先定义四根、五根的保留测试；若这些场景加入训练，报告中就不能称为未见数量迁移。

明确记录以下失败模式：下层片段被当成上层；相邻竹条被合并；交换层序仍选原角度/位置；细长边缘在缩放或掩码输出中丢失；数量或遮挡密度增加后失效；目标正确但动作忽略提示。若实例区域可靠而层序分类不可靠，再考虑成对关系模块；若实例区域都分不开，关系网络不能解决前置定位错误。

## 历史方案说明

以下保留 2026-09-26 VLM/RL 研究方案及旧静态评价规范。原先“双路身份标记＋全部成对关系＋可见吸附区域”的要求针对旧实验，不是当前全局单图上层分割的标注要求；原先先开展 VLM 静态评价的顺序也已被第 7 节替代。历史文字中的“当前”“第一版”和“首个可交付结果”应按旧方案理解。

## H1. 任务与已验证边界（历史）

目标是从两三根稀疏交叠的竹条开始，**先取最上层可分离的一根，放入收集区，重新观察，再逐层取出，直到料堆清空**。没有上下遮挡关系的两根可任选其一；允许邻条轻微被动位移，不把多根带起、损伤或未经验证的主动重排算作成功。

这里的“最上层”不是图像里最高的一个像素。对每对在交叉处接触的竹条，记录谁在上、谁在下，以及是否看不清。用 `A -> B` 表示 A 在交叉处压住 B、应先于 B 取走；没有被其他条压住且吸盘有可见接触区域的竹条才是候选。若层序或吸附区域证据不足，输出 `uncertain`，不能猜测下层目标。这个定义要用真实摆放和人工复核检查；RGB 图像本身不保证能判定所有接触关系。

当前七维 SmolVLA 使用双路 CameraSetV2 RGB、固定任务文字 `Pick one strip and place it in the collection area.`，输出六个绝对关节目标和吸盘指令。已有单根及双根抓放示范，但没有多根层序真值。当前适配器要求固定任务文字，也没有目标竹条 ID、框或掩码输入；`run_joint_smooth.py` 的旧单根模式在一次吸附—释放后结束，混训双根模式在两次释放后结束。历史 `rl_contract.py` / `rl_episode_contract.py` 绑定旧8维TCP路线，已随旧功能退役；原文可从 `69435fe` 查阅，当前没有七维在线RL接口。

## H2. 拟研究的分工与接口（历史）

```text
双路 RGB + 当前七维状态
  -> 视觉语言模型：竹条候选、成对上下关系、证据位置、不确定性
  -> 高层选择策略：选一个已确认的上层候选，或拒绝/请求复核
  -> 目标条件化 SmolVLA：对选中竹条执行一次抓放
  -> 独立执行约束 + AUBO
  -> 人工核验的单根结果、层序、剩余竹条数
  -> 重新观察，开始下一次高层决策
```

视觉语言模型（VLM）负责看图和提出**可核验的层序假设**，不直接生成关节命令。强化学习（RL）在一次抓放之间选择候选或决定是否暂缓，而不接管 25 Hz 关节伺服。吸盘指令或控制器 DO 读回只证明命令状态，不证明物理吸附。安全检查独立于 VLM 分数和 RL 奖励，模型不能通过奖励绕过它。

高层决策输入至少需要同一场景的双路图像引用、候选目标及上下关系、上一轮经核验的结果；输出必须能指向图像中的**唯一目标**或明确拒绝。当前 SmolVLA 无法接收这种指向，因此第一版可用旧模型做只读候选/动作诊断，不能声称“VLM 已让它抓指定竹条”。后续需要单独版本的目标条件化训练数据与模型。保持原始双路图像、七维动作和现有检查点不变；目标标记的具体编码方式（例如图像标记或新条件输入）应由离线对照决定，不能只换提示词后直接真机使用。

每次**物理动作后重新观察是固定要求**。在现有固定相机配置下，抓取前反复读取几乎相同的画面未必能消除遮挡；额外移动腕部获取新视角属于另一项主动感知能力，需单独验证和授权。首版 RL 可学的是在已观察场景中选哪个合格候选、何时因不确定而拒绝，不学习跳过动作后复核。

## H3. 最小验证顺序及现有评价器（历史）

1. **层序标注与静态基准。**先取得经单独授权采集的两三根静态摆放图像，为每个物理场景标注竹条实例、交叉处上下关系、可见吸附区域和 `uncertain`。按物理摆放划分开发/测试，不能把相邻帧分到两边。先衡量 VLM 的候选召回、错误层序、错误上层选择和拒绝率；证据不足时保留拒绝。
2. **目标接口离线验证。**针对相同场景比较“原 SmolVLA 自选目标”与“显式目标条件化”的预测是否真的随目标改变，并检查七维动作、吸盘时机及执行约束。没有带目标身份标记的多根示范和独立目标条件测试集前，不宣称新模型具备指定目标能力。
3. **高层结果数据。**每次实际尝试另存人工核验的目标、是否上层、恰好一根是否送达、邻条状态、保护停止、人工接管和剩余根数；不回填原始 `complete.json` 中的空物理结果。整堆成功定义为按有效层序逐根送达且最终无剩余；同时报告每一步首次成功率和整堆完成率。
4. **再决定 RL 实现。**先比较 VLM 直接排序、相同候选中的简单固定选择、以及使用已核验结果学习的高层选择策略。只有正负结果与场景划分足够支撑离线评价，才确定是单步候选排序还是多步离线 RL；在线真机探索另设门禁。奖励依据人工核验的物理结果，层序与进展可作辅助信号，安全代价单独记录。

本研究路线的首个可交付结果是**静态层序标注与 VLM 只读评价**。目前仓库没有按独立物理摆放复核的两三根层序真值基准，因此不能给 VLM 准确率、RL 收益或逐层清空成功率。没有静态基准、目标接口和结果真值时，不启动 RL 训练，也不把双根抓放试验解释成连续清堆验收。


### 静态评价文件

`evaluate_layer_order.py` 是硬件和模型均不加载的离线评价入口。人工真值与 VLM 预测分别为 JSONL，每行一个**独立物理摆放**。真值行需要 `schema_version=TopLayerTruthV1`、`scene_id`、`placement_id`（本次物理摆放的稳定编号）、`split`、冻结 CameraSetV2 的 `camera_set_sha256`、两路 `images`（各有 `path`、文件内容 `sha256`）、两或三根 `strips`（`id`、`contact_visible`）和覆盖每一对竹条的 `relations`。一个 `placement_id` 只保留一行；评价器拒绝重复摆放编号和完全相同的双路图像。预测行需要 `schema_version=TopLayerPredictionV1`、相同场景与相机哈希、两路 `image_sha256`、同样的 `relations`，以及显式的 `selected_id`（竹条 ID 或 `null`；缺字段不算拒绝）。

每个关系按 ID 字典序写 `first`、`second`，`relation` 取 `first_above_second`、`second_above_first`、`separate` 或 `uncertain`。`contact_visible` 仅指人工在图像中确认有可见吸附区域，**不是**可达性或物理吸附保证。第一版评价假设竹条 ID 已由人工在 VLM 输入中标明，因此它只检验层序推理与高层选择；实例定位、指定目标的 SmolVLA 能力和真实抓取成功率需分别评价。图像哈希、缺失关系或未知目标不匹配时拒绝统计。预测中的哈希是文件身份声明；评价器能核对声明与真值文件，不能独自证明 VLM 实际看到了该文件，需保存原始请求和响应供人工审计。

```bash
PYTHONPATH=src .venv/bin/python examples/phone_to_auboi10/evaluate_layer_order.py \
  --truth /path/to/human_truth.jsonl --predictions /path/to/vlm_predictions.jsonl --split test
```

输出报告给出可判定成对关系的准确率、不确定关系上的过度断言次数、正确顶层选择、错误选择、选择缺少自身预测层序支持的次数（`unsupported_selection`）、正确拒绝和不必要拒绝。`unsupported_selection` 指预测自己把所选竹条判为下层或与别条关系不确定却仍选择它；即使人工真值碰巧证明它在上，也必须单独报告这种猜测。没有真实场景及预测文件时不能运行出研究指标，也不以合成样本指标代替。

### 无图像阶段的标注准备与验收

现有双根抓放示教保存了双路图像，但尚未形成按以下规范标注的层序真值和独立摆放测试集；这些图像不自动构成层序基准。每个 `scene_id` 对应一次独立的物理摆放，两路图像来自同一静止场景。先按**物理摆放**划分 `development` 与 `test`，为每次摆放指定稳定的 `placement_id`，每次摆放只选一对图像进入评价；测试集在调整 VLM 提示词或策略前冻结。编号仍需人工核对：不同编号但实际未重新摆放的相邻帧，无法仅凭哈希自动识别。

1. 保留相机原始双路图像及其 SHA-256，不覆盖。另存供 VLM 看的两路副本，只在竹条远离交叉点的可见部位写 `A/B/C` 身份标记；每次摆放独立随机分配 ID，记录原始实例到 ID 的映射，不能按上下层、可抓性或摆放先后命名，也不要画上下箭头、接触边界或正确答案。两路图像中的同一根必须使用相同 ID。按开发/测试分别人工检查 ID 与顶层、可见接触区域有无固定对应，检查文件名和提示词是否泄露答案。真值中的 `images` 指向**实际送给 VLM 的身份标记副本**，评价器核对其文件内容哈希。原始图像仍需单独留存以供人工审核。
2. 人工逐根确认是否有可见的平坦吸附区域，并逐对标注交叉处的上下关系。无交叉且互不遮挡填 `separate`；看不清、同一对存在冲突的多个交叉点，或身份对应不可靠时填 `uncertain`。三根形成 A 压 B、B 压 C、C 压 A 等闭环时没有已确认的上层候选，应由第二人复核物理摆放和标签；若闭环确实存在，正确决策是拒绝。至少由第二人复核测试集的争议场景。
3. 用 `sha256sum` 计算两个身份标记副本的哈希，填入人工真值 JSONL；相机哈希固定为 `20de7adfd6ed9734c3a4329d86ab7e0ad08df9c6758d878d3c1302e2ac6423b4`。图像路径相对于真值 JSONL 所在目录解析。`placement_id` 从物理摆放记录抄录，不能仅按图像文件名重新编号。每一对 ID 只写一次，按字典序排列。
4. 先运行下方真值校验，再让 VLM 只读推理；从实际请求中记录两个输入文件的 SHA-256，并用它们填预测行的 `image_sha256`。VLM 若无法区分上层或吸附区域，应显式输出 `selected_id: null`。保存请求、响应、提示词、模型版本和人工提供的 ID 标记制作方法，避免测试集泄漏；这些元数据暂不计入评价器的机器校验。

```bash
PYTHONPATH=src .venv/bin/python examples/phone_to_auboi10/evaluate_layer_order.py \
  --truth /path/to/human_truth.jsonl --validate-truth-only
```

这个命令只检查标注结构、场景 ID、双路图像内容哈希和开发/测试数量；不会输出 VLM 准确率。没有真实图像时不制作虚假的基准数据。标注完成后的首要人工抽查是：上层候选确实未被其他竹条压住，`contact_visible` 仅代表视觉上可见的吸附位置，不代表机械臂可达或吸盘已吸牢。

## H4. 研究假设与近邻工作（历史）

待验证的核心假设是：**显式表示竹条上下关系及其不确定性，再利用真实分离结果学习高层选择，能以较少新增交互提高未见稀疏堆叠的逐层清空率。**应分别消融层序表示、拒绝机制、目标条件化和结果学习，并报告人工标注与现场交互成本。

“VLM 选目标 + RL”本身不是已证明的新算法。ThinkGrasp 已研究语言视觉模型在拥挤场景中的策略性移除，LENS 研究语言模型对拥挤场景的动态抽象，GR-RL 研究任务进展与潜在空间 RL。本项目的贡献需要由竹条压叠关系、不确定时的决策、真实分离反馈和受控对照来证明；这些论文的效果不能外推为本项目结果。

- ThinkGrasp: <https://arxiv.org/abs/2407.11298>
- LENS: <https://arxiv.org/abs/2607.19633>
- GR-RL: <https://arxiv.org/abs/2512.01801>

与现有路线的关系：保留当前七维 SmolVLA 作为低层基线；历史 8D C0/RL 契约仅供设计参考，不静默复用；ACT 和传统几何抓取不回到主决策链。所有真机环节仍沿用人工值守、独立安全否决和逐项授权。
